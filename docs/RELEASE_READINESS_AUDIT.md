# ReFind v0.2.5 — Engineering audit and release evidence

Audit date: 29 October 2026. Development baseline: `8331d90` (`codex/mvp-visual-finish`), preserving the accumulated visual work above `main` (`857acea`). Delivery: [`codex/release-readiness`](https://github.com/fahrezimahifa-ui/ReFind-v0.2.5/tree/codex/release-readiness), [draft PR #1](https://github.com/fahrezimahifa-ui/ReFind-v0.2.5/pull/1). The application remains an MVP; a production deployment is not included or certified.

## Prioritized findings

Severity describes impact under the stated conditions. A deployment prerequisite or tooling defect is not evidence of a remotely exploited application vulnerability. No Critical application vulnerability was demonstrated in this review.

| ID | Severity / confidence | Evidence and impact | Disposition |
|---|---|---|---|
| DEP-01 | **High — confirmed unsupported local database branch; deployment risk** | The installed client identifies MariaDB 10.4.32. Community maintenance for 10.4 ended 18 June 2024. Local PHP 8.2.12 / Apache 2.4.58 are also old patch builds. This is not proof of a particular exploitable CVE. [MariaDB policy](https://mariadb.org/about/#maintenance-policy). | **Production gate remains.** No XAMPP/server upgrade was attempted. Select maintained production patches and test the upgrade separately; CI uses a pinned MariaDB 10.11 image. PHP 8.2 support ends 31 December 2026: [PHP policy](https://www.php.net/supported-versions.php). |
| QA-01 | **High — confirmed tooling safety defect; conditional data-integrity impact** | Baseline `tools/prepare-test.py` unconditionally rewrote the QA local override. Several suites checked marker existence only; fixture enforcement checked the DB name without proving filesystem isolation. A misconfigured/junction-linked QA copy could touch shared runtime files or lose its connection settings. No such main-data damage was observed. | **Fixed.** Preserve existing local configuration; validate marker ownership, target identity, database, URL, session and filesystem links before synchronization. All current regression runners and the fixture repeat isolation checks. Offline refusal tests include main DB, foreign/missing marker and a redirected media directory. |
| CFG-01 | **Medium — confirmed reliability defect** | Baseline `app/config.php` assigned both configuration and auth-secret caches before validation. A synthetic reproduction against `8331d90` rejected the first call but returned the invalid value on the second call for both functions. Local overrides also lacked DB type/port validation. No HTTP authentication bypass was demonstrated. | **Fixed.** Validate before cache publication; validate supported keys/types/ranges, URL/session values and secret shape. Repeated invalid loads remain rejected. Existing valid local values and secrets are retained. |
| ERR-01 | **Medium — confirmed error-path fragility** | Baseline `page.php` reused configuration/template rendering while handling configuration failures. API exception handling was installed after application includes. A failure while rendering an error could escape the intended generic response. | **Fixed.** Install API handling before application includes, disable page error display early, and provide a configuration-independent HTML fallback. Offline tests verify generic HTML/JSON without synthetic secrets or filesystem paths. |
| HTTP-01 | **Medium — confirmed protection gap; exposure contingent on generated files** | The tracked root `.htaccess` did not deny `output/`. The existing installation relied on an ignored `output/playwright/.htaccess`; another checkout generating screenshots could omit it. The current local guard was present, so existing screenshot disclosure was not demonstrated. | **Fixed.** Deny generated output, development dependencies and tooling manifests through tracked rules. Environment-file variants are excluded from Git and Docker context (an explicit Git example template remains possible). The dedicated integration security suite checks actual Apache denials. |
| REC-01 | **Medium — confirmed consistency risk during concurrent writes** | `tools/backup-project.py` took a transactional SQL snapshot and then copied media while application writers could still remove referenced files. SQL consistency alone cannot make a later filesystem copy consistent. | **Mitigated with an explicit operational prerequisite.** The helper now refuses to start without `--writes-paused`, uses a new private destination, includes local configuration, and retains checksums. Operators must actually quiesce writers. A separate disposable restoration proof verifies synthetic SQL/media/secret recovery. No main backup or restore was run. |
| PERF-01 | **Medium — confirmed query amplification** | `app/repository.php::safe_item()` performed repeated photo, match, active-claim and own-claim reads per report. Native prepared-statement counters on 40 synthetic CI reports measured **180 Student / 120 BM projection statements**; 12 reports used 54 / 36. [Baseline measurement run](https://github.com/fahrezimahifa-ui/ReFind-v0.2.5/actions/runs/40785965408) later failed at browser launch; its completed SQL measurements remain valid partial evidence. | **Fixed; parity verified in CI.** Request-local batching in report/match lists and the BM list reuses scoped reads. An exact baseline projection oracle checks output/authorization parity and fixed query counts. Matching scores, locking, mutations and schema are unchanged. |
| CI-01 | **Medium — confirmed release coverage gap** | No GitHub Actions workflow or locked development dependency manifests existed; test PHP/browser paths were machine-specific. Local-only PASS history did not validate a fresh supported server environment. | **Implemented.** Pinned actions/images, locked npm/Composer tooling, PHP syntax, JS syntax, focused ESLint, PHPStan level 5, offline regression tests, redacted history scanning and disposable integration/recovery checks. Test execution is sequential; real runtime data and credentials are not uploaded. |
| DOC-01 | **Low — confirmed documentation drift** | Active README/install instructions mixed old repository URLs, historical ZIPs and current version claims; storage documentation called implemented photo collections future work. | **Fixed.** Consolidated current instructions in `INSTALLATION_AND_RELEASE.md`, shortened README, updated architecture/tooling guidance and explicitly labelled old release artifacts. Historical reports retain their original outcomes. |
| STATIC-01 | **Low — confirmed redundant expression** | PHPStan identified a redundant nullable MIME fallback after a successful `getimagesize()` shape check in `app/uploads.php`. | **Fixed.** Use the established MIME field after the false-result guard. Accepted formats, size/dimension limits and storage behavior are unchanged. |

This is a source-led audit plus the executions listed below, not an external penetration test or a guarantee that no vulnerability exists.

### History and dependency evidence

- Gitleaks **8.30.1**, downloaded from the official release with its checksum verified, scanned all **11 initially reachable commits** with external diff/text conversion disabled and output fully redacted. The first attempt using Git's external DOT conversion produced an error and is not the accepted scan.
- The complete untriaged run reported **26** generic-key alerts. Every alert was independently verified as a 64-character SHA-256 value in one of two historical release manifests. `.gitleaks.toml` excludes only those checksum lines in those exact files for that rule. The triaged scan and staged-source scan passed. No real credential was identified; this does not prove absence of every possible secret format or inaccessible history.
- npm installation audited **91 packages** and reported **zero known vulnerabilities** at that run. A separate read-only npm bulk-advisory query for the verified bundled **jQuery 3.7.1 / Bootstrap 5.3.8** headers returned no advisories for those versions; no runtime vendor bytes were changed. Composer locks PHPStan **2.3.4**. PHPStan runs at level 5 with no baseline suppressions. PHP/npm tooling remains development-only.
- Actions are pinned to commit IDs, container images to digests, and the Linux Gitleaks archive to its SHA-256. Workflow permissions are read-only; checkout credentials are not persisted, no deployment secret is supplied, and PR runs use `pull_request`, not privileged PR-target execution. Repository settings/permissions were not changed.

## Changes and compatibility

- Backend: `app/config.php`, `api/bootstrap.php`, `page.php`, `app/uploads.php`, and batched projections in `app/repository.php`, `api/items.php`, `api/staff.php`.
- QA/operations: shared Python/PHP/Node isolation and runtime helpers, safe preparation, read-only fingerprint/query profiling, sequential runner, baseline projection oracle, release security/offline regressions, synthetic recovery proof, QA-only smoke/visual tools and guarded backup helper.
- CI/dependencies: workflow, disposable Docker/Compose configuration, Docker context exclusions, Gitleaks policy, npm/Composer lockfiles and static-check configuration.
- Guides: README, architecture, installation/recovery, this audit, and historical storage/release descriptions. The PR diff is the complete changed-file inventory.

There is **no schema migration**, no rename, and no change to API routes/payload contracts, auth roles, match scoring or workflow status meanings. Invalid local configuration now fails consistently instead of being reused. New internal projection helpers do not change public fields. Existing valid configuration, secrets and credentials are preserved. The backup CLI now requires `--writes-paused`; release visual tools reject `--main`, and smoke targets QA.

No CSS, frontend application JavaScript, application templates, logos, bundled Manrope font or canonical SQL files have been changed relative to `8331d90`. The PR into older `main` includes the earlier visual commits as requested.

## Remaining risks and manual checklist

- **Before production:** select hosting, maintained PHP/Apache/MariaDB patches, HTTPS/canonical-host/proxy policy, least-privilege DB access and private filesystem ownership. Complete account provisioning and pickup-desk/privacy/operational ownership decisions. DEP-01 remains a production gate; the PR stays draft.
- **Local verification:** start MySQL/MariaDB at the configured 127.0.0.1:3306, then establish a read-only main fingerprint and run owned QA preparation/suites. Compare the main fingerprint afterward. Never initialize or repair the main database as a connectivity workaround.
- **Backups:** select protected/off-site storage, quiesce actual writers and perform an operator-run restore drill on a separate empty destination. The CI synthetic drill does not certify a real backup.
- **Devices:** check actual Safari/iOS/Android, touch/keyboard/screen reader, native zoom/tab suspension and low-powered motion/battery behavior. Desktop emulation does not replace these checks.
- **Scale:** the shared matching advisory lock and broad opposite-type row set remain unchanged to protect correctness. File-backed throttle/session state assumes one coordinated host; multi-node/distributed traffic and production load testing remain future work. No speculative matching-lock/index migration was applied.
- **Release review:** inspect the audit, exact test receipts and accumulated visual diff in draft PR #1. Resolve remaining deployment gates before a production-ready claim. Do not merge, deploy, change repository visibility/permissions or remove earlier branches automatically.

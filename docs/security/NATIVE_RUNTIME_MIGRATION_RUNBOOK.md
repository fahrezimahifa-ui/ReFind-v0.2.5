## Selected approach and review units

Use a Windows-native stack alongside XAMPP with complete verified PHP/Apache packages, app-local minimum CRT, minimal required extensions/modules, and an explicit configuration. This avoids replacing selected executable/DLL files inside the XAMPP bundle or changing the shared system CRT. Keep application source promotion separate from runtime promotion. Keep MariaDB migration in a later maintenance window after PHP/Apache qualification.

## Reproduce the isolated qualification

Use the security review branch's tools from an elevated/sandbox-approved terminal only for the private QA paths. Do not run them from main using arbitrary URL overrides. All runtime roots must be newly owned directories under LOCALAPPDATA/ReFindRuntimeQA. Reject junctions, aliases, foreign markers, unknown profiles and occupied ports. On this Codex MSIX host the logical LocalAppData path resolves into its private package LocalCache; the runner records canonical identity and sets canonical LOCALAPPDATA for its child processes only. Never change global environment or weaken realpath checks to work around virtualization.

1. Run `python -B tools/prepare-runtime-qa.py --source <frozen-checkout> --download`. The preparer creates a new root, user/SYSTEM ACL, public-only source manifest and synthetic configuration; it cannot start services or adopt an existing destination. Only pinned PHP/Apache archives are fetched by this command.
2. Resolve packages from [runtime-qa-packages.json](../../tools/runtime-qa-packages.json). All downloads use ordinary certificate validation. Check official/provider SHA-256 before safe extraction, reject off-origin/HTTP redirects, archive links, traversal, Windows aliases/streams and case collisions. A clear User-Agent resolves the Apache provider's earlier response; bypassing TLS is unnecessary.
3. For the Microsoft CRT bundle, follow only the verified HTTPS aka.ms to download.visualstudio.microsoft.com redirect, check the pinned SHA-256 and `Get-AuthenticodeSignature` Valid Microsoft signer/timestamp. **Do not execute the installer.** In this exact bundle the two validated MSCF cabinets start at offsets 479744 (140070 bytes) and 630000 (18091661 bytes). Extract with Windows expand.exe into the owned downloads staging directory; inspect the bundle XML mapping. Payload a4 is vcRuntimeMinimum_amd64; its nested cabinet contains the 12 minimum CRT DLLs. Verify each DLL's Microsoft signature and version 14.51.36247.0. Copy the complete minimum set into owned php/ and Apache24/bin only, stripping the payload `_amd64` filename suffix. Do not take DLLs from unrelated downloads/System32 or add MFC payloads. This recipe is pinned to this bundle; abort if layout/signatures/hash differ. App-local CRT needs future servicing with the application.
4. Safely extract the complete pinned Node and MariaDB distributions under that root; verify hashes before extraction. For long Windows paths use the extended-path API inside the validated root; never shorten guards, add junctions or change global long-path policy. Reusing an already verified private distribution requires comparing every copied file hash.
5. Run offline safety checks before `init-current`: test-runtime-qa.py, test-runtime-guard.py with REFIND_PHP set to the owned PHP, test-native-recovery.py and test-release.py. The CLI tools require the explicit runtime-upgrade environment and verify the source manifest, configuration and actual server @@port/@@datadir before mutations. Bootstrap refuses an existing datadir. The runner uses existing 10.4 binaries read-only only for a new synthetic server; no main config/defaults/datadir are used.
6. Run `python -B tools/run-native-qa.py init-current --qa-root <owned-root>`, then `test-current` using that root. Initialization includes existing rich synthetic fixture generators; original test assertions stay intact. The current profile uses 127.0.0.1:3312 and its own db/data, HTTP 8086 and optional TLS 8446. No main port 3306/80/443 or legacy QA server is accepted.
7. For LTS, use rehearse-native-recovery.py `capture`, `lts-import` and `runtime-principal` with the exact owned backup/root, then run-native-qa.py `test-lts`. New server: 127.0.0.1:3313 and db-lts/data. Production-style HTTP uses SELECT/INSERT/UPDATE/DELETE only; a separate QA CLI principal has test-schema DDL for fixtures/failpoints. This conditional synthetic configuration is not a proposed production config.
8. Run test-native-tls.py against the owned root and test-php-runtime-compat.py for synthetic legacy password/session compatibility. TLS uses a private seven-day test CA supplied explicitly to the client, no OS trust installation or ignore-errors flag. After the web TLS test prepares owned private material, run `python -B tools/test-native-db-tls.py --qa-root <owned-root>` once for explicit-CA SQL TLS and unrelated-CA rejection; it refuses existing negative-test material. This does not enable TLS in app configuration or clear WolfSSL advisory cases. Finally run `restore-old` against the frozen synthetic backup, into another newly owned root. Keep receipts, original failed attempts and all source/runtime fingerprints.

The dedicated runner catches failures and shuts down only its own Apache process tree and verified test DB. Before deleting a private tree later, resolve its absolute root, verify marker/ownership/no redirects and confirm no process uses it. No broad recursive delete is required for this task.

## Future WP04 logical database migration  -  approval required

Use MariaDB 11.4 LTS as the qualified candidate; current vendor release evidence is 11.4.13, maintained series through May 2029. Recheck the latest supported patch at implementation. A separate empty datadir avoids in-place major upgrade coupling. No main database operation has occurred. The tested Windows package reports WolfSSL 5.9.1; vendor backport/build qualification for newer conditional upstream advisories remains a WP04 promotion prerequisite. Do not replace WolfSSL DLLs independently.

- Pause all writers and take a coherent new logical dump plus matching media/config/session snapshot. Confirm table engines, character sets/collations, SQL modes, timezone handling, nullable event time, scheduled UTC conversion, unique indexes, transaction/locking semantics and application queries. Existing real grants/account definitions and view/routine DEFINER/SQL SECURITY clauses remain unverified and must be reviewed privately in the approved window. Qualify intended view/routine ownership with the minimal runtime principal; do not blindly carry privileged definers forward or mass-rewrite dump text.
- Initialize a new empty LTS datadir using its complete distribution. Import only the application's logical schema/data, routines/triggers/views as applicable. Recreate least-privilege application grants through a separate provisioning account with privately managed credentials; **never copy mysql privilege tables, a raw 10.4 datadir, or main root credentials**. Do not run ReFind setup/seeding against imported main data.
- Compare exact table counts and canonical value fingerprints including Unicode, nulls and timestamps; confirm password hashes unchanged without printing them; run all schema/workflow invariants and validate every media reference against the matching archived collection. Normalize only transport line delimiters in fingerprint serialization, never normalize database values to make differences disappear.
- The synthetic rehearsal imported 14 tables/591 rows unchanged and restored 436 matching media/config files; it exercises the mechanism, not the unknown size/content/engine diversity of the real database. A verified actual private backup restore remains mandatory before the real cutover.
- Change only the approved main DB host/port/user settings after successful import and checks. Keep prior datadir and configuration intact and stopped. Do not point two writer instances at the same database/storage/session collection. Perform the agreed acceptance checks before reopening writes.

## Coordinated rollback and data loss boundary

Before writes resume, a failed migration can return to the coherent pre-cutover database/media/config/runtime snapshot with no intervening accepted writes. Preserve failed candidate artifacts for diagnosis. Never run an older server against the newer datadir or restore SQL without its matching media/config snapshot.

After writes resume, reverting to the old snapshot would lose newly accepted records, uploads and workflow transitions. Stop writers again, capture the new state and seek an explicit forward fix or tested backward logical export/reconciliation plan; do not silently discard changes or assume a downgrade is supported. Record the agreed recovery point and downtime with the operator. Keep this approval separate from WP01 and runtime approval.
